# 上下文与记忆系统

本次改造把容量管理与记忆维护分开。容量管理只看实际准备发送的请求；记忆维护跟随用户输入和任务进展，不等待历史达到某个水位。

## 对话流程

用户输入 → 保存原文并更新工作状态 → 增量刷新证据 → 读取完整活动历史 → 加入技能、工具定义和固定规则 → 检查完整请求 → 模型与工具循环 → 保存回答与封存片段 → 更新工作记忆及候选知识。

活动历史包含压缩边界引用的近期消息和边界之后的新消息。原始时间线不受压缩影响。默认 30 条、单条 900 token 和五路比例已退出生产组装路径。检索 Top-K 仍是相关性选择，不代表固定空间配额。

## 容量处理

总窗口扣除回答预留和安全余量，得到可用输入预算。固定规则、当前问题、完整激活 Skill 和工作状态都参与计量；工具名称和描述不再同时在多个提示区域重复铺开。工具只声明自己的参数，项目范围由后端绑定。

完整请求超限时按下列顺序处理：

1. 对持久化的历史工具结果应用微压缩；缩短本轮工具观察和事件索引。记录仍保留，工作副本包含回查标识。
2. 从最低排名开始减少相关证据。原始证据仍可用工具重新检索。
3. 如仍超限，按 8、4、2 条近期保留目标尝试阶段摘要。问答和工具边界修正可能增加实际保留数。
4. 对每个候选用完整请求重新计量，包含当前系统规则、技能和实际工具 schema；只在达标且有收益时提交边界。全部档位失败不会把最后一档伪装成成功。
5. 必须保留的内容本身超限，或全部候选未达标时，明确返回 blocked，要求缩小输入或拆分任务。

生成摘要按完整待归档区间分块处理，不再直接把一份旧会话记忆当成整段历史的总结。模型不可用时存在提取式兜底；关键线索保留检查未通过时不会提交边界。摘要仍然是有损的，启发式检查不能证明所有语义细节都被保留。

压缩控制状态区分 applied、target_not_met、nothing_to_summarize、execution_failed、circuit_breaker_open。同样的请求未达目标后先暂缓；达到异常上限后冷却，冷却结束允许试探，成功后清零。容量不足不是服务异常。并发期间历史发生变化时，不提交基于旧快照的边界。

服务商 tokenizer 和隐藏包装可能与本地估算不同。安全余量不是严格的计数证明。服务端超限恢复最多一次，重试仍经过统一检查。辅助摘要和结构化提取也检查请求大小，过大时使用现有兜底，而不是继续发送。

## 工作记忆

工作状态独立保存在 working_state 中，包含有效条目、来源消息、修订信息和冲突。用户消息到达时就更新，不依赖本轮模型回答是否成功。

明确的表述可以直接更新状态，例如“目标：定位超时”“必须保持接口格式”“待办：补充回归测试”“更正：数据库有问题 -> 数据库已排除”“已完成：补充回归测试”。被替代或完成的旧条目保留历史状态，不再作为当前有效事实。

自动纠正只对能明确匹配的条目生效。无法确定用户在纠正哪项结论时，保留纠正原文并标记冲突，后续需核验，不猜测覆盖目标。自然语言提取和模型快照都有局限，不能当作任意语义纠错的保证。

备用快照合并把新内容放在旧内容之前，避免列表满后永远进不了新信息。模型快照仍需要与明确的失效条目核对。若较早一轮的提取在较新输入之后返回，该更新会跳过，防止覆盖新纠正。预算拦截的轮次仍封存，但不再调用记忆提取模型，也不生成长期候选。

## 工具记录与回查

工具返回后立即保存其实际返回值，再为当前 prompt 生成工作视图。可回查的是系统当时实际取得的内容；如果上游工具本来只返回片段，系统不会宣称保存了外部文件的全部内容。

原文回查支持消息标识、关键词、前后游标和字符偏移；封存片段支持片段标识和字符偏移。MCP 声明与执行均传递分页参数。首次记忆预取后仍进入工具循环，因此模型能够继续读下一页。具体仓库和会话由服务端固定，无效会话标识会报错，不会悄悄切到另一条会话。

“读取当时保存的结果”和“重新执行工具读取当前状态”在恢复说明中区分。消息 ID 用于前者，工作区和业务工具用于后者。模型仍受本轮工具步数上限约束，未读完不能声称已经核对全部原文。

## 项目长期知识

会话候选待人工批准后才进入项目知识。拒绝只作用于待审候选；撤销已批准知识使用独立动作。替代需要同一项目中有效的新记忆作为目标。

长期文档记录来源会话、封存片段、审核时间、适用范围、有效状态和可选有效期。到期、撤销、替代的文档保留原文供历史查看，但不进入默认关键词、证据或向量检索。向量索引即使尚未同步更新，也要用关系库中的当前状态核验命中。

主要接口：

| 操作 | 路径 |
| --- | --- |
| 审核候选 | POST /api/repos/{repo_id}/memory/candidates/{candidate_id}/approve |
| 拒绝待审候选 | POST /api/repos/{repo_id}/memory/candidates/{candidate_id}/reject |
| 撤销或替代已批准候选 | POST /api/repos/{repo_id}/memory/candidates/{candidate_id}/revoke |
| 停用或替代项目记忆 | POST /api/repos/{repo_id}/knowledge/notes/{source_id}/retire |

撤销/停用请求可提供 reason；提供 replacement_source_id 时表示由该有效记忆替代。新增项目记忆可提供 valid_until。页面支持查看候选状态、撤销已批准项，以及停用项目记忆；替代关系可通过上述接口提交。

删除原始会话与撤销项目知识分开。已批准知识可以继续保留，但标注 source_transcript_deleted，不再假装原始来源仍能访问。

## 性能与升级

历史定位、前后游标、关键词和限量读取在数据库中执行。完整活动历史使用分批读取，不把读取批次大小当作内容截断。证据层用源数据签名判断项目材料是否改变，只对改变的数据和当前会话材料做 upsert；避免每轮删除重建全部证据。

本轮工具原文即时持久化。记忆模型提取仍由封存链路同步执行，并有降级及过期更新保护；尚未引入独立任务队列。无模型或服务异常时不会因此丢弃已取得的原文记录，最终持久化仍取决于数据库提交成功。

旧数据库通过启动时的增量字段检查增加 working_state JSON 列；MCP 入口也检查该字段。升级不删除原始消息或既有项目文档。旧比例环境变量不再控制上下文组装。必须按实际模型服务设置窗口大小。

## 验收覆盖

回归测试覆盖：超过 30 条且单条超过 900 token 的历史完整保留；完整请求压缩后达标才提交；重要约束跨边界保留；压不动不提交且暂缓重复尝试；熔断冷却后恢复；旧结论被明确纠正；旧提取不覆盖新输入；工具结果即时保存和精确回查；模型继续读取下一页；MCP 传递偏移和拒绝错误会话范围；过期或撤销知识不会从陈旧向量复活；替代限制在同项目；证据刷新复用未变记录；字段升级可重复执行且保留原数据。
